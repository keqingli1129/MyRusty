Now, in C, macros are terrible. They're  implemented by something called the preprocessor,  
which doesn't know anything about C syntax. It  just takes a stream of source code text and does  
cut-and-paste with it, and then feeds that to  the real compiler. And, a macro invocation looks

basically the glue that gets used to fill all the  gaps in the language, so ... it's a whole thing.
In Rust, macros are nothing like that. Macros  are part of the grammar of the language,  
and they operate at the level of the abstract  syntax tree, not the source code text.  
So the definition of a macro will say,  "this argument must be an identifier", or,  
"this argument must be a complete expression",  and an invocation won't compile if it doesn't  
get what it expects. If a macro uses local  variables, those are in a separate namespace,  
so it's not possible to have name collisions. This  kind of system is called "hygienic macros", and it  
enables some quite powerful metaprogramming.  That'll be another whole video one day.
The reason println is a macro is because  it takes a variable number of arguments. It

Mutable variables - let mut
So by saying let mut, x is now  mutable, and we can assign to it. 
The reason for preferring immutability by default  is just that it makes code a bit easier to read

Scalar types
These are Rust's integer types. u means unsigned,  
i means signed integer. We have 8-bit, 16-bit,  32-bit, 64-bit and 128-bit integer types.
We also have usize and isize. These have the same  number of bits as a pointer. So on a 32-bit system  
usize and isize are 32-bit integers, and on  a 64-bit system they're 64-bits. usize is the  
type we use to index into arrays and count lengths  of arrays, because it'll always be big enough to  
handle the length of anything we can hold in  memory. usize gets used way more than isize.
Next we have floating-point types f32  and f64. These are the standard types  
defined by IEEE754. Obviously f32  is the 32-bit floating point type,  
and f64 is the 64-bit one. These are  equivalent to float and double in C.  
They take values with a decimal point. For  really big or really small values you can  
also do the scientific notation thing with an  'e', so 6.022e28 means 6.022 by ten to the 28.
We also have a boolean type called bool, with  the values true and false. True and false are  
keywords. A bool is one byte in size, but it only  ever holds one of these two values, which are  
represented as 0 and 1. It's undefined behaviour  to create a bool containing some other value,  
but you don't need to worry because  that's not possible in safe Rust.
And finally we have a type called char, which  is of course a ... "unicode scalar value". You  
all know what a unicode scalar value is, right? Of  course you do. It's basically a unicode codepoint,  
but without the weird surrogate codepoints that  were invented to make UTF-16 work. We don't need  
surrogates, Rust has great support for UTF-8.  So in Rust a char is always 32 bits in size,  
but only certain value ranges are allowed.  It's undefined behaviour to create a char  
with an illegal value, but, again,  that's not possible in safe Rust.
Char literals are written in single quotes, and  you can write anything that can be represented  
by a single codepoint, including lots of  emojis. Some emojis need multiple codepoints;  
for example anything with a skin tone  specified is made by combining codepoints,  
so that would have to be a string, not  a char. We'll get to strings eventually!

Sometimes you have many cases you want  to check for, and a long chain of if

pattern with a bell, and of course it returns the  string "subscribe". How did that get in there...
The next pattern will match the left square  brackets or the right square bracket. And we  
just keep going down the list until we  find a match. The first one wins. So if  
c is the digit 5 then we return the word  "five". If it's any other digit we return

And then we come to the underscore  pattern. Underscore is a wildcard,

Matching is required to be exhaustive,  because you have to return something  
for all possible cases. So the underscore  wildcard in the last arm is the catch-all,  
the default if none of the other arms matched.
In this example the expressions on the right  of the match arms are all just literal strings,  
but they could be any expressions, including  block expressions containing code that does  
stuff. Of course all the right-hand-side  expressions have to result in the same type,  
so the value can be returned from the match.
